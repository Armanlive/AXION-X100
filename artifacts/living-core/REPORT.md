# AXION Living Core rebuild — implementation report

Visual approval is pending. The approved reference was used as design guidance only; it was not copied, cropped, embedded, or added to the app as a raster asset.

1. **Repository files inspected:** `MASTER_PRODUCT_REQUIREMENTS_DOCUMENT.md`; `package.json`; `src/App.tsx`; `src/components/DesktopShell.tsx`; `src/components/WorkspaceChat.tsx`; both `src/components/AxionLivingCore.tsx` and `src/components/voice/AxionLivingCore.tsx`; `src/components/LiveSpeechMode.tsx`; `src/components/mobile/MobileShell.tsx`, `MobileChat.tsx`, `MobileVoice.tsx`, and `MobileNavigation.tsx`; `src/components/voice/VoiceControls.tsx`; `src/utils/voiceEngine.ts`; relevant Zustand definitions and execution/completion code in `src/store/useAxionStore.ts`; `src/types/index.ts`; `src/index.css`; `tailwind.config.js`; `vite.config.ts`. No AGENTS.md was returned by the repository search. The workspace does not expose a Git repository, so no Git diff/commit was produced.
2. **Actual implementation:** `src/components/voice/AxionLivingCore.tsx`. The outer `src/components/AxionLivingCore.tsx` re-export remains unchanged. Existing component props and imports remain compatible.
3. **Existing state model:** SpeechState = idle, listening, transcribing, understanding, thinking, speaking, parsing, working, ready, paused, error. The four visual states remain idle, listening, thinking, speaking; no new backend states were added.
4. **Real input data:** MicrophoneAudioAnalyser obtains microphone audio through getUserMedia and Web Audio. Despite its old RMS comment, its actual code averages frequency-bin magnitudes, normalizes by 128, clamps to 0–1, and uses analyser smoothingTimeConstant 0.65. No TTS amplitude analyser exists.
5. **Source files changed:** `src/components/voice/AxionLivingCore.tsx`; new `src/components/voice/AxionLivingCore.css`; `src/components/WorkspaceChat.tsx`; `src/components/LiveSpeechMode.tsx`; `src/components/mobile/MobileVoice.tsx`; `src/utils/voiceEngine.ts`. Screenshots, reproducible browser checks, and this report are under `artifacts/living-core/`. The production build regenerated `dist/`. No src-tauri/Rust/security/provider/backend files were edited.
6. **Rendering architecture:** Original native SVG geometry, gradients, masks, a bounded glow filter, and CSS animations. Single consistent 460-unit viewBox, responsive size variants, React useId for instance-specific SVG definitions. No image, canvas, Three.js, or runtime state-cycle timer.
7. **Central chamber:** Deep near-black/blue radial chamber, tiny singularity for ordinary Core instances, subdued internal energy, and a welcome-only AXION wordmark. Front-stream masking preserves central depth/readability.
8. **Spherical shell:** Shaded radial membrane, masked triangular mesh, meridian contours, 16 deterministic irregular filaments, and bright partial edge highlights.
9. **Cyan energy:** Blue/cyan gradients dominate the base shell and the varied front/back paths. Near-black environment and existing workspace structure are retained.
10. **Amber signature:** Separate warm paths, shell highlights, nodes, and wave accents. Idle Voice uses restrained amber; desktop welcome uses a somewhat stronger but secondary accent. Listening and speaking strengthen the warm layer. Thinking repurposes the secondary energy into violet.
11. **Orbit/depth:** Differently sized/tilted ellipses and segmented circular traces behind the opaque sphere, open foreground curves above it, and separate slow motions. Central masking creates additional depth separation.
12. **Particles:** 42 deterministic dust points plus a small set of nodes and triangular fragments. No randomly generated audio, particle storm, or hundreds of particle elements.
13. **Wave accents:** Four directional groups of lightweight SVG paths. The geometry and CSS motion are decorative. Only unmuted listening permits real microphone props to influence response scale and opacity; this is not a measured waveform display.
14. **IDLE:** Predominantly cyan/blue, 4.6-second shell breathing, 3.9-second nucleus cycle, 28-second back-field orbit, slower dust movement, low wave activity.
15. **LISTENING:** Warmer shell shading, stronger amber streams/waves, gentle inward shell motion, and bounded real mic response. Without available amplitude, only generic state animation remains.
16. **THINKING:** Violet/indigo palette, 11-second back-field circulation, 9-second node orbit, controlled shell activity. Displayed only while the existing isWorking flag indicates an active application request.
17. **SPEAKING:** Cyan and amber together, more visible waves, generic 1.8-second rhythm. This is explicitly not acoustic/TTS synchronization.
18. **Exact state sources:** Desktop welcome uses isWorking for thinking and otherwise idle. Desktop/mobile Voice track existing VoiceEngine onStateChange callbacks locally: observed speaking has priority, then isWorking, then observed listening when unmuted, else idle. RecognitionAdapter onstart establishes listening; synthesis utterance onstart establishes speaking. PTT-held state no longer forces the Core to listening. The three engine resume branches now return to idle while requesting recognition; listening is emitted on actual recognition start. Labels adjacent to the Core use the same resolved visual state. Existing broader SpeechState values remain available to the rest of the app.
19. **Real vs generic audio:** Input comes from the existing onAudioLevel callback. CSS response transitions smooth changes over 180ms, in addition to existing analyser smoothing. NaN and out-of-range input are handled; idle, thinking, speaking, and muted states ignore microphone values. No TTS amplitude was inferred or synthesized.
20. **Desktop:** Welcome sizing is clamp(350px, 47vh, 460px). Browser-measured boxes: 350px at 1280×720, 423px at 1440×900, 460px at 1920×1031. These are component boxes, not pixel-luminance measurements; inspect the screenshots for visible footprint. Geometry spans most of the box. Quick actions are compact controls retaining their existing handlers. Welcome copy no longer claims specialist orchestration. Existing message view still replaces the hero.
21. **Desktop Voice:** Same shared Core, observed-state mapping, matching textual status, and scrollable content when vertical room is limited. Existing controls and transcript functionality retained.
22. **Mobile:** Existing dedicated MobileShell/MobileVoice retained. Shared hero scales with viewport width/height; Voice content can scroll. Captured 390×844, 360×800, 404×756, and 430×932. The tested Core stays horizontally within the viewport and end-session controls remain above bottom navigation. Captures show microphone-denied/muted status truthfully.
23. **Reduced motion:** All Core keyframe animation and transitions disabled; reactive transforms disabled. Static geometry, state colors, and opacity remain. Verified via computed styles for every Core descendant in the four-instance fixture.
24. **Performance:** Removed the previous perpetual Core requestAnimationFrame loop. Geometry is deterministic and precomputed at module load; decoration uses CSS. Existing microphone sampling remains in the existing analyser. No FPS/CPU/GPU benchmark was performed and no such performance claim is made.
25. **Accessibility:** Decorative SVG hidden from assistive technology; enclosing Core announces its state. Voice state labels use role=status with polite announcements. Interactive Core instances retain click support and now support Enter/Space, tab focus, and a visible focus ring. Color is not the only state signal.
26. **TypeScript:** `npm.cmd run lint` → `tsc --noEmit`: passed on the final implementation. The production build also ran TypeScript successfully.
27. **Tests:** `npm.cmd test` → `node --test --experimental-strip-types src/tests/workspaceTransaction.test.ts`: 7 passed, 0 failed. This existing suite covers workspace transactions, not live voice. Additional `node artifacts/living-core/capture.mjs` browser checks passed for layout, no page errors, SVG ID uniqueness, and reduced motion. `node artifacts/living-core/check-audio-props.mjs` passed for eight explicit synthetic prop cases: idle/speaking/thinking ignore amplitude; listening reacts; mute/NaN/negative levels produce no response; excess input is clamped. Synthetic prop checks are not evidence of live audio capture.
28. **Production build:** `npm.cmd run build` → `tsc && vite build`: passed, 1666 modules transformed. Vite warned that a minified chunk exceeds 500kB (main JS approximately 1,014.94kB, gzip 231.57kB). No bundling/backend phase was started.
29. **Not runtime verified:** Native Tauri; actual microphone-level movement; successful live speech recognition; actual TTS playback/end-to-end synchronization; real provider-backed processing; performance over hours. Browser mic access was denied. State montage uses explicitly labelled component props, not fabricated live application states. No claim of visual approval is made.
30. **Later work / limits:** User screenshot approval; real-device microphone/TTS checks; broader existing voice lifecycle issues and the pre-existing chat-composer fallback behavior are outside this visual rebuild. Full visual parity with the richly rendered concept is not asserted: this is a lightweight vector reconstruction. Phase-2 mutation authority and all later product phases remain untouched.
